# 发布与隐私

公开仓库只提交通用源代码、说明和虚构测试数据。每个使用者自行在本机配置账号与密钥，首次运行创建自己的空数据库和连接码。

## 不提交的内容

- `data/`：数据库、DPAPI 保险箱、浏览器采集内容、聊天记录、邮件标题和连接码。
- 任何位置的凭据、Cookie、浏览器会话、数据库、日志、截图、网络抓包和导出的个人课程文件。
- `mcp-config.json`、`.env`、本机路径与编辑器 / 浏览器配置。
- 包含个人信息的排障笔记、实际使用记录或验证报告。

`.gitignore` 会忽略这些常见文件。不要用 `git add -f` 绕过规则，也不要把个人数据改名成源代码文件。已被 Git 跟踪的文件不会因添加忽略规则而自动退出历史。

## 提交前

```text
git status --short
git add <确认可公开的文件>
npm run check:staged
git diff --cached --stat
git diff --cached
```

`check:staged` 从 Git 暂存对象读取内容，而非只检查工作区文件；`check:public` 检查跟踪文件。两者只报告文件名、行号和规则，不打印匹配到的敏感值。GitHub Actions 也会运行检查。

检查器覆盖常见密钥格式、非示例邮箱、敏感会话参数、真实用户目录和私有文件类型，不能保证识别所有个人信息。截图、自由文本、改名的数据文件和提交作者信息仍需人工检查。测试中仅允许明确的虚构邮箱和少量用于拒绝测试的示例参数。

本地自定义数据目录同样需要排除。分享故障时使用可公开的复现样例，不附带真实账号、登录页面会话 URL、邮件、课程数据库或保险箱。
